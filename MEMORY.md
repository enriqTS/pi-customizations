# Memory

- OpenShell isolation is snapshot-based: `bin/pi-openshell` uploads the host repository to `/workspace/<basename>`, runs Pi there, then downloads changes on exit.
- The sandbox is not a live bind mount. Host VS Code can inspect the checkout before/after Pi, but must not edit it concurrently because download may overwrite host changes.
- The image contains the reviewed customizations at `/opt/pi-customizations`; it has the OpenSSH client for test fidelity but no SSH server, host keys, code-server, or VS Code integration. Outbound SSH remains blocked because network policy permits only ports 80/443.
- The image installs Debian `fd-find`; Pi recognizes its `fdfind` executable and will not attempt a network download at startup.
- The Debian Node image is intentionally retained as a small general-purpose base and adds Python, the latest Terraform release, and native-build prerequisites. Rust/Cargo/Rustfmt/Clippy come from the official current Rust image because Debian's packages were too old and omitted Clippy; Ruff and uv come from official Astral images. Tool caches use `/tmp` because the OpenShell filesystem policy does not allow writes to the general home directory. Pin tool images when a project requires reproducible versioning.
- The baked `terraform-guard` extension blocks Pi Bash-tool invocations of `terraform apply`; formatting, validation, and planning remain allowed. It is a guardrail, not a defense against deliberate shell-bypass techniques.
- OpenShell 0.0.102 treats an omitted `network_policies` block as no outbound authorization, not unrestricted internet: its proxy returns HTTP 403 for tunnels and Node surfaces this as `fetch failed`.
- General sandbox egress is intentionally enabled for HTTP/HTTPS only with a hostless endpoint, explicit public IPv4/global-unicast IPv6 CIDRs, ports 80/443, and binary glob `/**`. OpenShell 0.0.102 rejects top-level host wildcards and has no concise all-ports syntax. Codex credential routing remains narrowly scoped by `providers/pi-codex.yaml`. Do not upload secrets in a workspace.
- A sandbox launched from this repository snapshots both the working tree and `.git`; on exit it can overwrite host edits and commits made while that sandbox was active. Finish/close active wrappers before editing this repository, and verify `git status`/`git log` afterward.
- The wrapper synchronizes only current-project Pi session `.jsonl` files. It maps cwd-based host/sandbox session directories, rewrites session header `cwd` and local `parentSession` paths in each direction, and merges sandbox sessions back without exposing other projects. `PI_OPENSHELL_SESSION_DIR` explicitly overrides the default host project session directory. Do not modify the same project sessions concurrently on host and sandbox.
- Before downloading a Git workspace, the wrapper runs `git clean -fdX` in the sandbox so ignored build outputs do not overwhelm OpenShell's archive transfer or overwrite host ignored files. Ignored artifacts that must be returned need to be moved to a non-ignored path first.
- A sandbox retained after a failed sync can be reused from the original host project/subdirectory with `pi --recover NAME`, or synchronized immediately with `pi --recover-download NAME`. Recovery never reuploads the host checkout and deletes the sandbox only after successful session/workspace sync.
- The current filesystem policy grants the sandbox workdir plus selected read-only system/customization paths, not arbitrary host files.
- The OpenShell migration is complete. `openshell-environments` 0.1.0/API 1 owns the shared base/toolchain, policy, Git/workspace lifecycle, recovery, tests, gateway/security docs, and explicit image lifecycle. This repository owns Pi resources, settings/session synchronization, Codex patch/profile/provider behavior, entrypoint, and the thin adapter.
- `openshell-environments.version` pins compatibility. The installed default is `$XDG_DATA_HOME/openshell-environments/<version>` (or `~/.local/share/...`); `PI_OPENSHELL_ENVIRONMENTS_DIR` is the explicit development override. Never silently use an unversioned sibling checkout.
- Pi launches from `localhost/openshell-environments/pi:<version>` by default. Build/inspect/clean images deliberately with the shared `bin/openshell-image`; startup must not rebuild from source or fall back to a community image. Compose may manage the gateway, but OpenShell owns sandbox containers.
- Rollback to the old source-build launcher uses tag `pre-openshell-migration-20260811` at commit `05d90d3`. Preserve retained sandboxes before changing launchers.
- `bin/export-pi-release.mjs` produces deterministic API 1 asset and host-integration tar.gz archives from a clean commit using exact source-to-archive mappings, normalized metadata, per-member SHA-256, archive verification, and atomic replacement. It never exports the checkout or host Pi profile.
- Host export requires validated digest-pinned compatibility metadata and the exact asset archive so its checksum can be verified. The portable launcher lives in `packaging/pi-openshell` and resolves hook/helpers/profile/metadata relative to the package; exports do not install, publish, or activate it.
